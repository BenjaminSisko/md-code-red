Running an older Ansible?

Day One's first command is ansible --version — believe what it says. On ansible 2.9 or older (common on RHEL 8-era boxes): fully-qualified names like ansible.builtin.copy do not resolve (that routing arrived in 2.10) and systemd_service was still called systemd (renamed in 2.14). Tick "ansible 2.9 compatibility" in the Task Builder and generated plays use the short names 2.9 understands — on 2.9 the posix-collection modules (firewalld, authorized_key, mount…) were built-in short names too. On 2.10+, keep FQCNs, and install any needed collections with the "Install a collection offline" entry. This kit's flag dictionaries were extracted from ansible-core ; an older CLI may lack some listed flags — the decoder will honestly call your older CLI's real flags UNKNOWN if they differ.

Honesty line

This kit's dictionaries are curated and dated. The authorities are on your box: ansible-doc, man, /usr/share/doc, and each daemon's own validator. When this file and your box disagree, the box wins. The kit never guesses: anything it doesn't know, it says so.
